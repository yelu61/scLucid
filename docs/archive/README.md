# Documentation Archive

Everything under this directory is historical provenance, not a current user or
implementation contract.

- `design_notes/` preserves superseded architecture, audit, and roadmap drafts.
- `marker_curation/` preserves the batch-level evidence used to build the live
  queues in `docs/marker_resources/`.
- `sphinx_source_legacy/` preserves the retired Sphinx documentation source.

When archived text conflicts with current behavior, use code and tests first,
then maintained API/user documentation, current implementation policy, and the
canonical roadmap. Do not edit archived material to describe new behavior;
update its maintained successor instead.
